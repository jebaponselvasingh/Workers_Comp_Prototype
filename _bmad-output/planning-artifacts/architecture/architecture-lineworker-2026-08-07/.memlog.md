- (decision) AD-1 Layered service architecture (API-first): React SPA -> FastAPI REST/SSE -> service layer -> PostgreSQL; agents live behind the same FastAPI boundary. Binds all. Prevents business logic leaking into the SPA (prototype computed everything client-side). [ADOPTED via research synthesis + user]
- (decision) AD-2 Deterministic financial/rules logic (benefit calc, priority score, reserve check, payment schedule, SLA) lives in versioned server-side services and is exposed to the LLM only as tools; LLM output may never originate a financial figure. Prevents hallucinated dollar amounts and duplicate rule implementations.
- (decision) AD-3 Single PostgreSQL 16 database owns relational data, pgvector embeddings, LangGraph checkpoints, and audit log. Prevents split-store drift and a second backup/security domain. Verified: pgvector adequate <10M vectors.
- (decision) AD-4 All writes go through service-layer commands that emit an audit event (user, role, action, resource, before/after, timestamp) in the same transaction. Prevents unaudited PHI mutation; the prototype's inline edits become PATCH commands.
- (decision) AD-5 AI is local-only: all inference through Ollama on the internal Docker network (never published); no cloud model APIs. qwen3 chat model, bge-m3 embeddings; model names are config, not code. [ADOPTED user constraint]
- (decision) AD-6 Agent layer is LangGraph (Python) compiled StateGraph with AsyncPostgresSaver checkpointer; one supervisor graph routes quick-action keys and free chat; every graph node that writes claim data must pass interrupt() human approval. Prevents ad-hoc agent loops and unapproved AI writes.
- (decision) AD-7 Server-authoritative RBAC: persona->employer assignment lives in HandlerEmployerAssignment table enforced in FastAPI dependencies; the client never filters visibility. Prevents the prototype's client-side HANDLER_MAP scoping from surviving into production.
- (decision) AD-8 Rules that business users may tune (priority weights, reserve bands, SLA targets, action-list caps) are JDM JSON documents executed by GoRules ZEN engine embedded in Python, versioned in the DB; statutory benefit math stays in typed Python (property-tested), not ZEN. Prevents rule forks between code and config.
- (decision) AD-9 Frontend is a Vite React 19 SPA: server state exclusively via TanStack Query (no Redux); shadcn/ui components; copilot chat via assistant-ui LangGraph runtime over SSE. Prevents mixed state-management idioms across screens.
- (decision) AD-10 Every derived field the prototype stored (daysOpen, risk, siuReview, rtwBlocked, paymentDue, totalPaid) is computed server-side at read time or by rules engine, never persisted as editable columns. Prevents stale-derivation drift.
- (constraint) Local-only AI (no cloud LLM) is a hard user constraint; HIPAA-adjacent WC data must not leave the network.
- (constraint) Excel WC_Feature_Element_Details.xlsx row 29/64/65/66 define write-back semantics (review/confirm/approve-payment) that must become audited API commands.
