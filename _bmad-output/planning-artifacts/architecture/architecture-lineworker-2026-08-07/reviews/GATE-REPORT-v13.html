Root cause — one move relocated the gate but left four things unreconciled. The write-approval gate went from a node-agnostic step (v1.2: any writing node passes interrupt(); registry raises without an approval token) to a core-bound middleware on the create_agent free-chat node. The rest of the spine still assumes:
  1. Not every write goes through the core. The RTW-letter write is a deterministic QAS router node (AD-14, routes before any LLM call) — it never enters the middleware's loop.
  2. The middleware's decision model is richer. The new edit decision and multi-tool batching don't map onto AD-6's single pending_approval + version-CAS.
  3. One write is deliberately gate-exempt (AI-insight refresh) — but AD-13's registry raise forbids any unapproved write.
  4. The double gate (middleware + registry raise) has no specified handshake — so it deadlocks or is vacuous.

Recommended remediation — one coherent v1.4 amendment

All five HIGH findings collapse into one architectural move plus reconciliation of the richer decision model.
  1. Re-establish the single node-agnostic write gate as the AD-6 invariant — exactly one step where a claim write executes, always behind approval. Realized via the middleware on the core and by routing QAS write nodes through that same gated step. (CF-1, CF-4)
  2. Reconcile single-flight with batching — one pending write per interrupt, or plural pending_approval with per-action CAS. (CF-2)
  3. Constrain edit — args-only, never the target entity; CAS on drafted versions; audit all three decisions. (CF-3, CF-10)
  4. Carve out rag-refresh explicitly as a non-gated, non-write-tool command. (CF-5)
  5. Specify the resume wire contract per decision, and mid-approval scope re-resolution; move caller to context-only. (CF-6, CF-7, CF-9)
  6. Pin langchain to a concrete minor; note the 4th decision; drop the “F1 gate” jargon; pin record_copilot_approval to AD-4. (CF-8, CF-11, CF-12)
