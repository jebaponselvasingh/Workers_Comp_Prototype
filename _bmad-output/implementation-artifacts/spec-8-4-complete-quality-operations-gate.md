## Intent

**Problem:** The quality bar Stories 1.1–8.3 built incrementally is nearly complete but has never been closed as a gate. Three things are missing outright — the AD-15 sprint-status↔spec **bijection lint** (which `ci.yaml`'s own header defers to "a later story"), any declaration of which checks are **required for merge**, and a **prod boot runbook** — and the prod compose profile still carries four hazards that earlier stories deferred to this one by name: dev database passwords that survive into the prod render, no `restart:` policy on any service, no `hostssl` enforcement on the Postgres side of 8.2's TLS, and cookie/`ENV`-keyed defaults resolving to their dev branch behind a TLS ingress. Separately, `api` waits on `ollama: service_healthy` — a boot-time hard dependency on a completed model pull that contradicts AD-14 and makes a fresh host with no registry access unbootable.

**Approach:** Audit every NFR-7 element against the workflow as it actually is, close the gaps that are wiring rather than new suites, and make the two conventions that are currently prose mechanical: a bijection lint in the `lint_log_phi` idiom (importable detectors + its own unit test) and a settings-as-code required-checks manifest that a test holds equal to the workflow's job list. Then finish the prod profile — `:?` guards on the credentials, `restart: unless-stopped`, a prod-only `hostssl` `pg_hba`, explicit overrides for every setting whose default keys off `settings.env` — write `deploy/DEPLOYMENT.md` (clean host → prerequisites → volume-encryption pre-flight → boot → health → smoke, plus the deferred-decision registry), and **execute** a clean boot against it, recording durations and deviations the way Story 8.3's drill did.

## Boundaries & Constraints

**Always:**
- **This story verifies and wires; it does not author missing suites.** Every NFR-7 element was owed by an earlier story. Where an element exists, prove it runs and is required. Where the gap is a seam between two existing halves (the SSE frame vocabulary spelled once on each side), close the seam. A wholly absent suite is a defect to record in `deferred-work.md` and surface, not to write here.
- **The gate must not be able to pass vacuously (AD-15).** That is the standard every check in this story is held to: a lint whose input set can go empty, a job whose two run-steps are both `if:`-gated on a value that could be unset, an assertion bounded on a string that can match at index 0 — each passes green while testing nothing. Story 8.3's review found exactly that shape in a posture test; assume it is here too until each new assertion is driven to a failure and observed failing.
- **Anchored tag greps, both directions.** `@story:1-3` must never match `1-30`. Every grep this story writes or touches carries `\b` (or an equivalent bound), and the bijection lint's own tests include the `1-3`/`1-30` case.
- **AD-14: startup gating orders boot; it never creates a hard runtime or boot dependency on the model server.** `api` and the claim screens must come up on a host where Ollama cannot pull. Ollama's own health still reports whether models are loaded — that is the degradation signal, not a gate on the console.
- **AD-5 re-verified in the finished prod profile:** ollama publishes no port in any render, model tags stay env-driven, no cloud path.
- **No new table, role, grant, RLS policy, or migration.** This story writes CI config, compose overlays, deploy docs, posture tests and one e2e spec. Any change that appears to need a schema or grant change is out of bounds — see Block If.
- **`docker compose -f deploy/compose.yaml up` on a clean checkout keeps working** (Story 1.1). Every hardening this story adds lands in the prod overlay or behind a profile, never in the dev base's default path. The two dev-base edits it does make are deliberate exceptions that loosen or clarify rather than tighten: the `api`→`ollama` condition, and the `ollama` healthcheck's probe.
- **`.env.example` and the compose files stay in set-equality** — 8.3's rule: a knob referenced by a compose file or a shipped script is documented, and a documented knob is referenced. Any new prod variable joins both sides.
- **CI never mutates `sprint-status.yaml`.** The bijection lint reads it and nothing else writes it.

**Block If:**
- Closing a gap appears to require setting `ENV: prod`. `api/app.py:437` refuses it by design while persona login is the authentication mechanism; the overlay's *absence* of that line is asserted by `test_deploy_tls_posture.py:386`. The IdP decision is Deferred and is not this story's to make. Document the deferral with its trigger and override the individual `env`-keyed defaults instead.
- Closing a gap appears to require a new DB role, a widened grant, a schema change, or an edit to an applied migration.
- An NFR-7 element turns out to be wholly absent rather than partially wired — i.e. closing it would mean authoring a suite an earlier story owed. Record it and HALT rather than silently expanding scope.
- The clean-host boot cannot be executed at all (container runtime unavailable, images unbuildable). An unexecuted runbook does not satisfy AC 2, and recording one as executed would be a lie in a compliance document.

**Never:**
- Do not choose, install or configure an observability/alerting stack, an IdP, MinIO, a worker-container scheduler, or K8s/HA. Documenting each as deliberately-not-built *is* the AC 3 deliverable.
- Do not delete or weaken an existing spec or test to make the full suite green. AD-15: specs are amended, never deleted.
- No UI work. If an incidental UI surface is touched, the prototype's light palette stays canonical (Story 1.1).
- Do not duplicate the spine's Deferred prose into `deploy/`. The registry names the item and its trigger and links to the spine.

## Design Notes

**1. The bijection lint lives in `server/scripts/`, not in `e2e/` or `.github/scripts/`.** The story's Project Structure Notes suggest "`e2e/` or repo `scripts/`", and either would work as a script. Neither can carry the thing the story actually requires of it — "the bijection lint has its own unit test (orphan spec ↔ orphan story key both fail)". `e2e/` has exactly one runner, Playwright, so a unit test of the lint would become a browser-project spec that boots nothing, and it would land in `e2e/stories/`, where the lint itself would then count it as an orphan spec. `.github/scripts/` is worse: `check_model_ports.py` proves the shape works, but that directory is reached by no linter, no type-checker and no test runner in this repository — ruff runs `. ../deploy` from `server/`, mypy's `files` list stops at `server/`, and pytest's `testpaths` is `tests`. `server/scripts/` is the one tree where all three already arrive, and `lint_log_phi.py` + `test_log_phi_lint.py` is the exact precedent: importable detectors, a thin `main()`, and a test file that runs the detectors over the real tree *and* over hand-written smells. The lint reads two paths outside `server/` and takes them as arguments so the tests can point it at fixtures. This is a deviation from the story's suggestion and it is recorded here rather than silently taken.

**2. Why `service_started` rather than a better `ollama` healthcheck.** The tempting fix is to make Ollama healthy sooner — probe the API rather than the pull marker — and keep `service_healthy`. That trades one dishonesty for another: the marker means *models are loaded*, which is exactly the fact the copilot's availability depends on, and a healthcheck that goes green before the pull would report a model server that is up and has nothing to serve, which is the failure the Story 6.1 comment was written about. The real error is not the healthcheck; it is using it as a gate. AD-14 says the claim screens have no hard dependency on the agent runtime, and Story 6.6 built the seam (`agents/degradation.py`) that makes an outage report `ai_unavailable` instead of failing. A boot-time `service_healthy` on a two-model pull defeats both on the one occasion it matters most: a fresh host with no route to the registry, where today the stack hangs for up to thirty minutes and then fails with the console never having started. So the condition relaxes to `service_started` — ordering preserved, readiness demoted from gate to signal — and the healthcheck keeps its meaning, gaining only an endpoint probe (`ollama list`, which talks to the container's own HTTP API using a binary that is certainly present) so AC 2's "health endpoint on every container" is literally true here too.

**3. A required-checks manifest, because the alternative is a claim about a settings page.** Branch protection lives in GitHub repository settings and cannot be created, read or asserted from this working tree. The story allows "docs or repo settings-as-code" and the docs-only reading is the weaker one: a sentence in a runbook does not fail when somebody adds a sixth job and forgets to require it. `.github/required-checks.yml` plus a set-equality test makes the *completeness* of the list mechanical even though the *enforcement* stays manual — the same trade `test_deploy_tls_posture.py` makes about a compose file CI can render and never boot. What remains genuinely unenforceable goes to `deferred-work.md` rather than being implied away.

**4. The SSE element is closed by a seam test, not by a new suite.** NFR-7 names "one integration test drives the real SSE + assistant-ui stream protocol end to end", and the audit found both halves real: `tests/test_copilot_threads.py` drives the actual endpoint and asserts `text/event-stream`, the frame sequence, exactly one `done` and exactly one `error`; `web/src/api/copilot.test.ts` drives the client parser through truncation, cancellation and a final frame with no trailing newline. What is missing is not a test — it is the join. The event names are spelled in `api/routers/copilot.py` and re-spelled in `web/src/api/copilot.ts:491`, whose own comment says a string spelled twice stops matching the day one of them changes, and nothing checks. Writing a third, genuinely cross-process integration test would be re-doing Story 6.5's scope; asserting that the two vocabularies are the same set closes the actual hole for a few lines. If the pattern that reads the TypeScript side matches nothing, the test must fail rather than compare two empty sets — the vacuity rule applies to this story's own additions first.

**5. The prod `pg_hba` is a mount swap, because one file cannot be two policies.** 8.3 shipped `pg_hba.conf` with `host` records and said, in the spec and again in `deferred-work.md:1087`, that turning them into `hostssl` would enforce TLS in prod and break dev and e2e in the same edit — and left the prod half here with the file now in place to change. The mechanism is already in the tree: `compose.prod.yaml:85` mounts `nginx/tls.conf` over the baked `default.conf` for exactly this reason. A second file mounted at the same container path in the prod overlay only is the same move, keeps the dev file untouched, and is checkable by text — which is what the posture test asserts, in both directions, so neither file can quietly become the other.

**6. The clean boot runs under its own project name.** A twelve-day-old `lineworker` stack is running on this host, on the pre-8.2 `pgvector/pgvector:pg18` image and with no `ollama` container — i.e. a stack that predates two of this epic's stories. Reusing it would prove nothing about a clean host and tearing it down with `down -v` would destroy a developer's state to make a point the runbook can make safely. `-p` with a distinct project name gives fresh volumes and a fresh network without touching it, and the deviation is recorded like 8.3's e2e-profile drill: the boot is real, the profile it ran on is stated, and the reader is not left to infer a rehearsal that did not happen.
